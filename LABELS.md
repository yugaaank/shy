# GitHub Labels

The following labels are suggested for organizing contributions to shy:

| Label | Description | When to Use |
|-------|-------------|-------------|
| `good first issue` | Helpful for newcomers and new contributors | Mark issues that are simple, don't require deep domain knowledge, and have clear acceptance criteria |
| `help wanted` | Community friendly issues | Invite collaboration on any open issue |
| `bug` | Reports a bug or unexpected behavior | Used for bug reports in issue templates |
| `documentation` | Issues related to documentation | Updating README, CONTRIBUTING.md, comments, or other documentation files |
| `enhancement` | New features or improvements | Feature requests and enhancement requests |
| `performance` | Performance optimization issues | Profiling, benchmarking, or optimization tasks |
| `plugin` | Issues for plugins or integrations | External plugin development or integration requests |
| `question` | Questions from the community | Questions about usage, configuration, or implementation |

## Using Labels

1. When labeling an issue or pull request, use the appropriate label from the above list
2. Update labels as issues progress through their lifecycle (e.g., `good first issue` → `help wanted` when someone starts working on it)
3. Use a maximum of 2-3 labels per issue to keep classification simple

## Adding Labels

These labels should be created in the GitHub repository settings under "Labels". If you need assistance creating them, reach out to the repository maintainer or check the GitHub documentation.

The labels will help:
- New contributors find suitable starting points (`good first issue`)
- The community understand what types of contributions are most needed (`help wanted`)
- Maintainers quickly categorize and prioritize incoming requests
- Contributors know which issues need code changes, documentation updates, or are purely questions
